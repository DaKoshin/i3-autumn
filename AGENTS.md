# Правила роботи зі збіркою робочого столу

## Межі доступу та приватність

- Працюйте лише з конфігураціями й компонентами робочого столу, необхідними для поточного завдання.
- Не відкривайте, не копіюйте, не індексуйте, не змінюйте та не передавайте вміст `~/.ssh/`, `~/.gnupg/`, `~/.aws/`, `~/.kube/`, `~/.password-store/`, `~/.local/share/keyrings/`, браузерних профілів, сховищ паролів та інших сховищ облікових даних.
- Не читайте приватні ключі, токени, паролі, `.env` / `.env.*`, `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, `credentials*`, shell history, cookie-файли, `/proc/*/environ` чи повний набір змінних середовища. Не запускайте `env`, `printenv`, масові дампи dconf або рекурсивний пошук по домашньому каталогу.
- Не використовуйте SSH-агент, credential helpers або секрети для автентифікації; не змінюйте SSH/GPG, PAM, sudo, polkit, firewall чи системні дозволи у межах цієї задачі.
- Якщо окреме наступне завдання справді потребує доступу до секрету, зупиніться й отримайте чіткий дозвіл саме на потрібний шлях і дію. Ніколи не виводьте значення секрету в чат, логи, репозиторій або зовнішні сервіси.
- Нові віджети не повинні виконувати мережеві запити, збирати телеметрію, читати секрети або додавати неперевірені сторонні плагіни. Не використовуйте `curl | sh` чи `eval` для даних із меню.

## Безпечні зміни сесії

- Перед заміною конфігурацій створюйте датовану резервну копію тільки конкретних файлів, які буде змінено.
- Не завершуйте сесію, не блокуйте екран, не перезавантажуйте й не вимикайте комп'ютер під час перевірок.
- Зміни i3/Polybar запускайте тільки в i3; не додавайте їх у глобальний GNOME autostart або загальні shell startup-файли.
- Не змінюйте конфігурацію GNOME, display manager або системну розкладку без необхідності та явного дозволу на відповідну зміну.
- Перевіряйте синтаксис і доступні локальні компоненти. Не встановлюйте пакети й не пишіть за межі робочої папки без належного дозволу середовища.

Це інструкції для агентів, а не захист операційної системи: програми, що працюють від імені користувача, зазвичай мають доступ до його файлів. Не стверджуйте, що цей файл створює sandbox для плагінів.
